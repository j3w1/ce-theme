# Claude Design System bundle

`exports/design-system/` packages the foundation in the file layout of Claude's Design System artifact type, so Claude Design can read the brand book, tokens, recipes and assets and design with them. It is generated by `pnpm generate` and drift-checked by `pnpm check`; never edit it directly.

## Sources

| Bundle path (`project/…`) | Generated from |
| --- | --- |
| `tokens.json`, `tokens.css` | `tokens/*.tokens.json` (DTCG) through `scripts/design-system.mjs`. Variable names match `exports/tokens.css` (`--ce-…`); semantic colors stay aliases of palette colors. Every token's `$description` becomes its usage note. |
| `components/bundle.css` | `recipes/recipes.css`, plus one line mapping `--ce-font-family` to the design system's `--font-sans`. |
| `README.md`, `components/<Name>/README.md` and `preview.html`, `assets/<Group>/README.md`, `components/Cover/preview.html` | Authored in `design-system/`. |
| `pricing.md`, `accessibility.md` | `docs/` (copied). |
| `assets/Icons/*.svg` | `site/data/icons.mjs`, drawn in ink `#111111`. |
| `licenses/noto-sans-OFL.txt` | `public/licenses/`. |

Binary files are not copied into the repository. `exports/design-system/publish.json` lists them with their repository sources: the Noto Sans latin variable font (from `node_modules/@fontsource-variable/noto-sans`), the product photos that component previews load from `project/media/`, and the supplied logos, product photos, campaign references and icons that become the design system's asset library.

There is no JavaScript component bundle: components are the framework-neutral HTML/CSS recipes, and previews are static markup styled by `bundle.css`.

## Publishing and re-syncing

Publishing is a manual owner action, never part of CI. To refresh the owner's design system after a foundation change:

1. Run `pnpm generate` and `pnpm check` on the reviewed commit.
2. Upload each `assetGroups` file in `publish.json` to the design system's asset store when it is new or changed, and record its blob id in the design system's `project/design-system.json` index under `assetGroups.<Group>.files`.
3. Publish the changed `project/…` files from `exports/design-system/` plus the `files` entries in `publish.json`, then the index last with `lastChange.via` naming the commit.

Edits made directly in the design-system page are not written back to this repository. Make lasting changes here and re-sync.
